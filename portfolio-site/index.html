HOW I THINK ABOUT BUILDING

Good software is more than the happy path.

These projects are exercises in making the rules visible: who can act, which records belong together, what happens when a request fails, and what the system cannot prove.

01

Data has to hold together.

Relational constraints and contract checks make invalid states harder to create, even when the interface is bypassed.

02

Permissions belong server-side.

Role controls are enforced at the API or contract boundary. A hidden button is never the security rule.

03

Say what the evidence means.

A database row or on-chain hash can support review. It cannot prove that aid arrived or that a submitted receipt is truthful.
